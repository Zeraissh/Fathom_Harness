02主流对照（右侧到底该是什么）

应用右侧是什么何时出现窄屏形态
Cursor编辑器 tab（预览/差异）你打开时；不占默认版面标签页/全宽
VS Code编辑器分栏 / 次级侧栏手动开；按工作区记忆抽屉
v0 · Bolt · Replit实时预览首个产物出现时自动；可钉住切换 / 全屏
Claude · ChatGPT Canvas画布仅当内容够格；否则没有画布全屏切换
共识一句话：内容驱动、按需开、关是可记住的、窄屏变全屏切换——没有任何一家在空状态挂一个常驻空列。

03提议：三条规则

R1 · 出现没有内容就收起，有内容才打开 判据 = 工作区文件非空 ∪ 有打开的预览/产物。欢迎页与对话一视同仁；空目录的欢迎页不再挂空列。（收起的形态保留"细条把手"，不是 0 宽消失。）
R2 · 窄档永不自动展开；把手角标 → 点开是全屏 sheet 运行中写盘不抢屏，只在把手亮角标「有新产物」；点开 = 全宽 + 遮罩 + Esc/点外关闭。（修 61% 遮挡与"回不来"）
R3 · 尊重手动收起 = 你的决定，直到你下次再开 同一内容不反复自动弹；新产物仍只发角标（宽档允许"新路径产物开一次"）。（对应主流"dismiss 要粘住"）

04遮挡矩阵（"应该挡什么"的答案）

场景遮挡判定形式
宽档 side✓ 允许布局占位（中心列有地板），不是浮层压内容
窄档 · 你点开的 sheet✓ 允许用户主动 + 一键即关；全屏看内容是主流选择
窄档 · 自动弹的全屏✗ 禁止打断读流；改为角标提示
任何档 · 不请自来的浮层压输入框✗ 禁止输入框是不可侵占区（当前窄档在犯）

05两个待拍板

Q1 · 欢迎页 + 有文件：右列默认开还是默认收？
推荐
默认开
有文件时树是真入口，引导第一课就教它；空目录按 R1 收。
默认收
欢迎页只服务"开始说话"一件事，更素净；要看得自己开把手。
Q2 · 窄档有内容时（自动）怎么呈现？
推荐
角标 → 点开全屏 sheet
不抢屏；点开拿满宽度看内容，Esc/点外即关。
角标 → 点开仍是 240 浮层
改动最小，但代码/图在 240px 里读不了，治标。
自动开全屏 sheet
内容优先（v0 风格），但会打断正在读的执行流。
