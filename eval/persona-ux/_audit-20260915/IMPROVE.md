## 2. 总裁决：现在像什么产品

对 **聊天优先的知识工作者**，第一次打开已经像一台中文聊天稿台：默认 Work 脸、占位「说要做什么…」、发送叫「发送」、新手卡第 1 页「打一句话，回车」、空态有「做纪要 / 做一页 / 带出处问答」。Work 普通人话 `POST /api/runs` 是 **200**，不再被领域包 409 挡在门外。

对 **要签字的委托方 / 安全岗**，默认先问、批准卡是「要新建或改 …」+ 允许/拒绝、停止说「已停止」并声明写入不回滚——这三句成立。预览会先宣布还没写的文件并报读取失败；提问卡会顶掉计划短表。指挥中心在提问挂起时说什么，本轮没拍到。

对 **Cursor / 编辑器惯用者**，仍然不是家。`@` 终于列文件了，右侧也有「文件」二字，但树写「先选一个工作目录。」而发送栏已经是 `web-a`；`@hello-code.txt` 点完输入框还是 `@hello`；没有行内 diff。桌面是同一张网页外框，开始菜单 0 个 FATHOM。

对 **Claude Code / CLI 惯用者**，终端比 9 月 14 日可信：`--help` 写清计划门、`run --help` 能开、无 `--yes` 印「需要确认，请加 --yes」、`--yes` 横幅 `yes=true`、续跑已完成 id 停而不考古。没有斜杠 REPL。Web 上勾「计划」容易先变成三道 `ask_user`，计划卡钉不住。

对 **Vibe / 画布向**，有「做一页」芯片和预览坞，没有先于聊天出现的空白画布，也没有可点的三维页。

一句话：**这是一台会跑任务的中文聊天台，外加一块爱抢戏的预览坞；还不是编辑器，也还不是指挥台。**

## 4. 按信息架构的改善建议

只写用户能感觉到的改法：改名、默认值、藏旋钮、补空态、补一句帮助。不写架构重写。

### 冷启动

- 保持第 1 页「打一句话，回车」和「稿件、纪要、问答都可以从这里开始。」
- 欢迎卡已经承认「现在只能在这个窗口下指令。」留下。飞书示例把 4173 改成「当前 UI 端口」（或打印 `AGENT_UI_PORT`）。
- 右侧树在发送栏已有目录时，不要再写「先选一个工作目录。」——改成列出那个目录，或写「与下方写入点相同：web-a」。

### 发送栏

- Work 脸普通人话继续 200；**不要默默 `facade=design`**（编排 `mode` 仍是 `single`）。设计管线只在用户点了「做一页 / 做纪要」芯片之后开始。
- `@` 点选后插入完整 `@hello-code.txt`（或相对路径），不要停在 `@hello`。
- `#` `/` `$`：没有补全就别吃这些键。`/` 要么弹出命令面板，要么不当命令。
- 「引用会话」名字可以留，欢迎卡那句「旧对话用引用会话」要始终在附件旁边再出现一次，避免和文献出处混。

### 审批 / 计划门

- 没有写盘成功，就不要说「产物画布已打开：某文件」，也不要先报「读取失败——文件可能已被移动或删除。」`b-code-card.png` 上批准条在坞下面，键看得见；C1 无头点击超时不当作用户点不中的证据。

- CLI：TTY 改一行再 y 仍待补测；帮助原文已经写对，别改回去。

### 直播与过程

- 流式：本轮补拍没等到「正在想」正文（审批先到）。直播条在提交瞬间有「新任务已提交」，保留。
- 停止：C5 原文正确。正在停止时若同时出现重连横幅，把「运行仍在服务端继续」和「已请求停止」写成一句，避免两张嘴。

### 文件 / 预览 / 点评
