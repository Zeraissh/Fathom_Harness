## 2. `/`：修成打开命令面板

仓库里本来就有命令面板（Ctrl+K），所以这是**接上既有能力**，不是新造：

- 打**在第一格**（输入框为空）时 → `preventDefault` + 打开命令面板；
- 有内容时 → 照常插入 `/`（路径、除法、日期都要用它，不能占键）。

活页验收（`p4-verify.mjs`）：`/` 在第一格打开面板且没写进输入框；`看下 src` 之后打 `/` 得到 `看下 src/` 且面板不开。

## 3. `#` / `$`：复现「没反应」，但改判为不是缺陷

两条证据：

1. **全仓没有任何用户可见文案承诺 `#` 或 `$` 有特殊含义**（grep 过 `ui/public/` 与 `docs/`）。`@` 有承诺（欢迎卡写着「输入 @ 可按文件名找这个文件夹里的文件」），所以 `@` 必须有行为；`#`/`$` 没有。
2. 它们**也没有被吃掉**：打 `#` 后输入框里就是 `#`，打 `$` 就是 `$`，面板不开、值不丢。

审计的原话是「没有补全就别吃这些键」。它们已经符合这一条。所以这不是"空响缺陷"，是**普通字符**。改判并留档，不当成待修项——否则会为了消灭一个不存在的承诺去发明一套 `#`/`$` 语法。

## 4. 点文件必开（与 P1 绑定的那条）

**这是我 P1 造的缺口**：右列合成一列后，若列停在「文件」面板，CSS 会让预览坞 `display:none`——于是从文件树点一个文件，坞"打开了"但屏幕上什么都没发生。

修法：坞打开时广播 `preview:open`，右列据此切到预览面板。用事件而不是让坞直接改 `data-panel`：右列状态归它的所有者（`railPref`），坞绕过它写属性会在下一次 `paintRightRail` 被覆盖。

活页验收（`p4-verify.mjs`）：点之前右列确实停在「文件」；点之后 `data-panel=preview`、坞 `hidden=false`、实测 **395×446 像素**、正文就是文件内容 `ping`。

## 5. 看「改了什么」：先实拍，再补逐行改动

**实拍现状**（`p4-changes.mjs` 第一版）：右栏「变更」分区**已经**列出了本 run 触碰的文件 + 操作徽章（写入/修改）+ `触碰 N 次` + 大小 + 时间；`hasDiffMarker: false`、`hasLineNumbers: false`。也就是**缺的正是「改了哪几行」**——审计原话「没有行内 diff」。

**决定：补。** 数据路径是决定性的——`edit_file` 的入参必带字节精确的 `old_string` / `new_string`（`src/tools/edit-file.ts` 的 `required`），工具自己也说「不做通用 LCS：改动形态已知，按位置出 hunk 既精确又便宜」。所以**不需要磁盘上的旧版本**；而整文件覆盖写（`write_file`）拿不到旧版本，那种就不给，不编。

实现：`editHunksFromTimeline(state)`（纯函数，只收**成功**的编辑）→ 面板展开时先铺「改动 N 处」，逐行 `-`/`+` 元素（按行着色，读屏逐行念）。

**活页验收**（真实归档 run `46f123df`，含 3 次成功 `edit_file`）：

```json
{
  "rowCount": 22,
  "hunksFound": true,
  "title": "改动 2 处",
  "delCount": 5,
  "addCount": 7,
  "firstDel": "-       var bh = 9.5;",
  "firstAdd": "+       var bh = 9.5;"
}
```

5 条 `-`、7 条 `+`，内容是那次真实编辑。**5/5 判据成立。**

## 6. 顺带修掉一个堵住两处功能的既有缺陷

实拍这条时撞到两层遮挡，第二层查下来是个真缺陷：

`#detail-drawer` 被创建成 `hidden`，而 `styles.css:334` 是 `[hidden] { display: none !important }` —— **`<summary>` 也一起被藏掉**，抽屉彻底不可达。事件流（P5 的成组）与「变更」的逐行改动**都在这个抽屉里**，两处独立功能一起被堵死。这与 `app.js` 对用户说的「完整过程也在下方「运行详情」」自相矛盾。

修法：**只收起，不藏掉入口** —— 去掉 `hidden`（`<details>` 默认就是 `open=false`），`patchUsageFooter` 里那行改 `hidden` 也改成 `open = false`。

连带的既有测试「用量脚注和 Loop 抽屉默认不显示」按新语义改：仍然默认**收起**（`open=false`），但 `hidden=false` 让入口可见。a11y 那套不受影响（axe 本来就不扫收起的 `<details>`）。

**真实用户路径（四步，已写进脚本）**：展开「运行详情」→ 点 `#rail-toggle` 展开详情栏（`.detail-rail--collapsed` 会把 `.rail-body` 设成 `display:none`）→ 找到「变更」行 → 展开它。前两步此前一步都走不通。
