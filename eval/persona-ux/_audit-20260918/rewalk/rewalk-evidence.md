## 2. 最差的几处（按「会不会逼用户离开」排）

### 2.1 审批摩擦：一次一行编辑 = 5 张卡

4199 真 run（任务「把 hello-code.txt 第一行的 ping 改成 pong，只动这一行」、逐次审批、deepseek-flash），屏幕上依次出现 **5 张批准卡**：

1. `要运行：ls -la; echo "---"; cat -A hello-code.txt 2>/dev/null | head -20`
2. `要运行：ls -la; echo "---"; cat -A hello-code.txt; echo "---"; od -c hello-code.…`
3. `要运行：cat -A hello-seed.txt; echo "==="; cat preview-seed.html`
4. `要改 hello-code.txt`
5. `要运行：od -c hello-code.txt; echo "---"; ls -la; cat -A hello-seed.…`

加重情节：第 1 张放行后，bash 被沙箱拒了（日志原文 `✗ bash 失败 Refused: shell redirect target escapes the working directory`），模型在思考里写 `Let me avoid /dev/null.`，于是**又出第 2 张卡**——用户看到的是「批了又批」，拒绝原因只在运行日志里。

- 默认先问是登记过的不变量（不推翻）。但**读文件（cat/ls/od）也逐张卡**，等于每次了解现状都要人按一次。
- 对照：用户自己的 34 分钟长 run 走的是 auto-run（`approval_resolved … "actor":"auto-run"`，95/101 自动），说明自动放行不是没人会用；**default 逐次审批 + 模型爱用 bash 逐文件读 = 新用户第一件小事就吃 5 张卡**。
- 候选（产品决策，不是缺陷）：读类工具（read_file / glob / grep / 只读 bash）默认免问；或「本 run 内同类只读命令短期自动允许」。

### 2.2 花费串账（N5 的形状还在）

- 4199 是**隔离宿主**（独立 `AGENT_RUN_HISTORY_DIR`），屏幕上仍写 **`今日 $5.59`**——这 5.59 是**本机全局台账**（含 4173 的 run），隔离 history 隔不开；我的 run（+$0.0022）当场进了这个数。
- ARIA 名称是诚实的：`本机今日 $5.59（全部工作目录） · 今日已用 2 次`——**但可见文字只有「今日 $5.59」**。
- 4173 上是 `这次 $3.70 · 今日 $5.59`：**「这次」已经有了（做对了）**，「今日」仍没标口径。
- 候选：可见文字补「本机」二字；或按 workdir/history 分账。

### 2.3 窄窗（<948）左栏不让位

- 700×900：左栏 292 不动（`railMode=overlay` ✓ 契约对），但对话可用宽只剩 700−292=**408 < 416 地板**；浮层开着时可见对话仅 **~168px**（实测 rail x=460，宽 240，贴右）。
- 430px（Claude 窗口内嵌 pane 实测）：左栏 292 + 主区 700 全宽重叠 + 浮层 240，三层互相压着——超出契约梯子（700 起），不算违约，但「窗口一小就不能用」是真实形态。
- 左栏自动收：**没有**（只有手动「隐藏侧栏」）。
- 候选：视口 < 预算边界时左栏自动收成图标条。

### 2.4 密度：发送栏与空态

- 发送栏 150px 高：输入框**上方 4 个控件**（项目 / 工作目录 / 模型 / 运行设置），下方**两条常驻注**（`写入仍受工作目录边界约束`、上下文环）。
- 空态两组建议芯片共 **9 枚**（`下一步`×5：先对齐做法 / 点名一个文件 / 看右边的文件 / 看一张图 / 设个定时；底下 `做纪要 / 做一页 / 带出处问答 / 更多稿件`）+ 4 行说明；完成后又换一组 6 枚。
- 不是「错」，是「每次打字都在看工程面板」的体感来源。
- 候选：scopebar 收成一行摘要（`web-a · kimi-k3 ▾`），点开才是 4 个控件。

### 2.5 对话把机器藏得很干净（观察，不立案）

- 一次编辑的会话视图只有 4 块：用户消息 / `Thought Process` 折 / 最终回答+`验证 · 4` 折 / 产物卡。**5 张审批卡、1 次沙箱拒绝在会话里零痕迹**（grep 会话正文：`批准/允许/拒绝/审批/Refused/失败/重试` 全部 0 命中）——全在「运行详情」的 907 条日志里（其中 approval 条目 95、error 23）。
- 「对话优先、机器下钻」可能就是这个设计，但也可能是「看不懂它到底干了啥」的来源。留作问题。

## 9. 窄窗左栏让位（2026-09-18 当天，第三刀）

- **先复现，结果大幅缩水**（同 P4 纪律）：今天的活页里 ≤700px 是既有的**堆叠布局**
  （左栏成顶部横条、对话全宽在下），不是当时记的「三层互相压着」；真正吃紧的是
  **701–707px** 那一小段（对话 409–415 < 416 地板）。规则按残量定：视口
  < 左栏实测宽 + 416 + 240（与右列 side↔overlay **同一份预算**）**且有会话在开**时，
  左栏默认收起；收起用 `persist:false`（偏好是另一个键，回宽按它恢复）。
- 实测：900px 开着会话 → 左栏收起、对话拿满 900（原 608，右列同时从覆盖档升回并排档）；
  回宽 1200 → 按偏好恢复；手动展开后不与之打架；只看列表（欢迎态）不让位。
- **顺带抓到并修掉一个既有缺陷（浏览器实测才看得见）**：`resize` 的 rAF 节流在
  页面被遮挡（`document.hidden`）时回调永不落地，`if (raf) return` 从此**吞掉所有
  resize**——连派发合成事件都唤不醒重绘（本轮验证第一遍全被它搅乱，一度以为
  接线没生效）。修法：隐藏页直接同步算 + 时间上限兜底 + `visibilitychange` 补帧。
  同族：本项目 2026-08-06 修过「rAF 在隐藏标签页不触发」。
- 测试：`ui-rail-policy` +7（边界/无会话/量到 0 不抖/宽屏/接线锁/节流兜底锁）。
